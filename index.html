Fix: x-model.blur cleanup crash on DOM removal

Alpine.js Discussion #4738 — Regression from PR #4729

1. Core Bug: x-if removes x-model.blur input

Type a value, blur the input, then click Remove. On current Alpine release this crashes.

2. Form submit after sibling removal

Type in both fields, blur each, remove the second, then submit. The form's pending updates array must not be corrupted.

What happens and why

Before fix (crashes)

1<input x-model.blur> inside a <form>
2Wrapped in x-if (or removed via Livewire morph)
3Toggle removes the input from the DOM
4el.form is now null → cleanup crashes
TypeError: Cannot read properties of null
(reading '_x_pendingModelUpdates')

After fix (works)

1Capture let form = el.form at registration time
2Cleanup callback uses the captured reference
3Reference stays valid after element detachment
// x-model.js line 87-92 if (el.form) { let form = el.form // captured here let syncCallback = ... if (!form._x_pendingModelUpdates) ... form._x_pendingModelUpdates.push(...) cleanup(() => form._x_pending...) // safe }
Note: This page loads Alpine 3.14.9 from CDN (the current release with the bug). The demos above will crash in the browser console when you remove the input. After the fix is applied, these demos work without errors. Open your browser DevTools console to observe the TypeError.
